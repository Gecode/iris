# Ideas for Iris 1.0

This file collects candidate changes for Iris 1.0 found during the Iris 0.1
work: formats that 0.1 cannot express or expresses awkwardly, surprising 0.1
behavior found while writing the Specification, and what Gecode 7 needs. Each
entry names the problem and where it was found. The 1.0 design reviews this
list (`PLAN.md` §10.1).

## Ideas

### Distinguish missing sections arms from line failures

Iris 0.1 uses `E-LINE-MATCH` for both a failed `line` statement and a
missing required sections arm: Gecode can produce identical complete
diagnostics for them. Give missing sections arms a distinct diagnostic in
Iris 1.0 so adapters can distinguish the failures without parsing the reader
spec. Found while building the [0.1 error registry](../spec/0.1/errors.md).

### Make contextual keyword handling consistent

Iris 0.1 accepts keyword-named declarations, but top-level `format:int`
fails because metadata dispatch comes first. `format` also fails to stop
an open range, unlike statement keywords, and `else if:int` is accepted
as a declaration. Review these dispatch rules together. Found while
specifying [reader-spec syntax](../spec/0.1/05-reader-specs.md#56-statements-declarations-and-blocks).

### Give format metadata a consistent position

Iris 0.1 permits repeated format declarations, including after `instances`,
and keeps only the last name. Decide whether metadata should have one
position and whether repetition should be an error. Found in
[§5.9](../spec/0.1/05-reader-specs.md#59-format-metadata).

### Decide how repeated options combine

Iris 0.1 permits repeated, interleaved alphabet and sections options.
Alphabet values replace earlier values; sections terminators accumulate
while the last store name wins. Consider a more consistent rule or reject
repeated options. Found in [§5.7](../spec/0.1/05-reader-specs.md#57-types-ranges-and-options).

### Make discard names consistent

Iris 0.1 treats `_` differently by position: declarations, lists, and
captures can discard; `let`, `param`, `type`, and comprehensions reject it;
`as` and `each` accept it; `store _` stores an entry named `_`. Decide which
positions should permit a discard name and what it means. Found in
[§5.4](../spec/0.1/05-reader-specs.md#54-names).

### Reject NUL consistently in reader-spec syntax

Iris 0.1 admits a literal NUL as a punctuation token outside strings and
comments, then fails in syntax parsing. Gecode's printed diagnostic can
also end at that NUL. Consider a lexical error with an escaped character
in the diagnostic. Found in [§5.2](../spec/0.1/05-reader-specs.md#52-white-space-and-comments).
