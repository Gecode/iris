# Ideas for Iris 1.0

This file collects candidate changes for Iris 1.0 found during the Iris 0.1
work: formats that 0.1 cannot express or expresses awkwardly, surprising 0.1
behavior found while writing the Specification, and what Gecode 7 needs. Each
entry names the problem and where it was found. The 1.0 design reviews this
list (`PLAN.md` §10.1).

## Ideas

### Share one sections obligation across alternative header patterns

The [nonogram format](https://stevocity.me.uk/nonogram/fmt2) allows
`width N` or `columns N` for a dimension, and `height N` or `rows N` for
the other. Iris 0.1 gives each sections arm its own required/optional
status and repetition check. Supporting these aliases needs separate
optional arms and extra checks for one logical dimension. Consider
alternative patterns in one arm, sharing captures and a single occurrence
requirement. Found while copying the [nonogram reader spec](../formats/nonogram/nonogram.iris),
which accepts only the explicit `width` and `height` forms.

### Distinguish missing sections arms from line failures

Iris 0.1 uses `E-LINE-MATCH` for both a failed `line` statement and a
missing required sections arm: Gecode can produce identical complete
diagnostics for them. Give missing sections arms a distinct diagnostic in
Iris 1.0 so adapters can distinguish the failures without parsing the reader
spec. Found while building the [0.1 error registry](../spec/0.1/errors.md).

### Make contextual keyword handling consistent

Iris 0.1 accepts keyword-named declarations, but top-level `format:int`
fails because metadata dispatch comes first. `format` also fails to stop
an open range, unlike statement keywords, and `else if:int` is accepted
as a declaration. Review these dispatch rules together. Found while
specifying [reader-spec syntax](../spec/0.1/05-reader-specs.md#56-statements-declarations-and-blocks).

### Give format metadata a consistent position

Iris 0.1 permits repeated format declarations, including after `instances`,
and keeps only the last name. Decide whether metadata should have one
position and whether repetition should be an error. Found in
[§5.9](../spec/0.1/05-reader-specs.md#59-format-metadata).

### Decide how repeated options combine

Iris 0.1 permits repeated, interleaved alphabet and sections options.
Alphabet values replace earlier values; sections terminators accumulate
while the last store name wins. Consider a more consistent rule or reject
repeated options. Found in [§5.7](../spec/0.1/05-reader-specs.md#57-types-ranges-and-options).

### Make discard names consistent

Iris 0.1 treats `_` differently by position: declarations, lists, and
captures can discard; `let`, `param`, `type`, and comprehensions reject it;
`as` and `each` accept it; `store _` stores an entry named `_`. Decide which
positions should permit a discard name and what it means. A top-level
`store _` entry survives, but a store in an enclosing repeat iteration is
omitted from that repeat's columns and discarded with its frame. Found in
[§5.4](../spec/0.1/05-reader-specs.md#54-names) and
[§7.4](../spec/0.1/07-structure.md#74-repeat-forms-and-termination).

### Reject NUL consistently in reader-spec syntax

Iris 0.1 admits a literal NUL as a punctuation token outside strings and
comments, then fails in syntax parsing. Gecode's printed diagnostic can
also end at that NUL. Consider a lexical error with an escaped character
in the diagnostic. Found in [§5.2](../spec/0.1/05-reader-specs.md#52-white-space-and-comments).

### Decide whether alphabets should read Unicode characters

Iris 0.1 alphabets map bytes: `éa` supplies three cells, and each UTF-8
byte is an independent member of `blank` and `strip`. Decide whether Iris
1.0 should map Unicode scalar values instead. Found in
[§6.10](../spec/0.1/06-types-and-values.md#610-alphabets).
The [repeated-options idea](#decide-how-repeated-options-combine) also
applies to alphabets.

### Review numeric promotion and sentinel equality

Iris 0.1 `num` promotion can round earlier large integers. Mixed numeric
sentinel comparison converts to binary64 and can consume a mathematically
different integer. Decide how Iris 1.0 should preserve numeric values and
whether mixed sentinel comparisons should be exact. Expression comparisons
also round mixed operands: `9007199254740993 == 9007199254740992.0` is
true in 0.1. Include expression comparisons in that decision. Found in
[§6.2](../spec/0.1/06-types-and-values.md#62-scalar-reading-and-numeric-promotion)
[§6.9](../spec/0.1/06-types-and-values.md#69-sentinel-and-end-of-line-lists),
and [§8.6](../spec/0.1/08-expressions-and-checks.md#86-comparison).

### Make offset timing and zero adjustment explicit

Iris 0.1 declarations evaluate offset before reading; lists evaluate it
after termination. Adding the default zero also changes a read negative
zero to positive zero. Review consistent evaluation timing and whether an
omitted offset should perform addition. Found in
[§6.7](../spec/0.1/06-types-and-values.md#67-offsets-and-evaluation-order)
and [§3.5](../spec/0.1/03-data-model.md#35-floating-point-values).

### Review structural size bounds for empty arrays

Iris 0.1 checks dimension products in order: `[46341][46341][0]` is too
large despite having no scalar leaves. Review the structural limits for
empty shapes alongside the work-budget policy. Found in
[§6.6](../spec/0.1/06-types-and-values.md#66-fixed-size-arrays-and-empty-rows).
[§10.2](../spec/0.1/10-work-budgets.md#102-idle-work) specifies the separate
idle charges for positive dimension prefixes before the first zero.

### Add bounded float and numeric reads

Iris 0.1 ranges read integers only; neither bounded `float` nor bounded
`num` reads are available. Consider those forms for Iris 1.0, with explicit
bound and comparison rules. Found in
[§6.4](../spec/0.1/06-types-and-values.md#64-integer-ranges).

### Review capture boundaries and matching diagnostics

Iris 0.1 captures use greedy boundaries without backtracking:
`{x:float}end` fails on `2end` because the numeric candidate includes `e`,
and `{x}ab` fails on `xaYab` at the first `a`. A word capture's NUL boundary
also depends on whether a literal immediately follows it. Review whether
these boundaries should change and how diagnostics can explain a failed
match. Found in [§7.2](../spec/0.1/07-structure.md#72-line-patterns-and-captures).

### Make empty computed-column types and depths explicit

Iris 0.1 uses int/scalar fallback metadata for `let` in a repeat.
Consequently `repeat 0 {let c="s"}` produces an empty int column at depth 1,
while an executed `let` can establish a different type and depth from its
result. Decide how empty computed columns should determine their metadata.
Found in [§7.5](../spec/0.1/07-structure.md#75-column-construction-and-missing-rows).

### Keep structural diagnostic source locations stable

When Iris 0.1 sections ends through a last arm with an executed body, a
missing-arm diagnostic uses the body's last executed reader-spec line.
Its input position still identifies the last arm's matching-line start.
Review which structural statement should own the reader-spec position.
Found in [§7.8](../spec/0.1/07-structure.md#78-sections).
Post-body idle exhaustion likewise retains the last executed body statement's
line rather than the repeat's line; include that case in the review. Found in
[§10.6](../spec/0.1/10-work-budgets.md#106-exhaustion-and-error-locations).

### Review remainder overflow at the minimum integer

Iris 0.1 reports integer overflow for -9223372036854775808 % -1,
although the mathematical remainder is zero. Decide whether remainder
should keep division's overflow guard. Found in
[§8.4](../spec/0.1/08-expressions-and-checks.md#84-integer-arithmetic).

### Make aggregate type acceptance independent of leaf presence

Iris 0.1 integer aggregates accept empty float and string arrays, but
reject those types when leaves are present. Decide whether aggregate
argument types should be checked independently of emptiness. Found in
[§8.8](../spec/0.1/08-expressions-and-checks.md#88-functions).

### Make check quantification and whole-array access explicit

Iris 0.1 implicitly ranges checks over repeated fields, with shallow
exceptions for direct names in size, defined, and comprehension domains.
Thus count(a), size(a), size(a[0]), and size(row.a) can see different
levels; an empty lifted collection can make an otherwise false condition
pass. Review explicit quantification and clearer whole-array access.
Found in [§8.12](../spec/0.1/08-expressions-and-checks.md#812-record-names-and-field-access).

### Review which record indices check witnesses retain

Iris 0.1 check witnesses omit active execution-frame indices and explicit
record-selection indices. A check on an explicitly indexed failing record
can have an empty record_path. Review richer diagnostics while retaining
0.1's distinction between execution context and the failure witness.
Found in [§8.13](../spec/0.1/08-expressions-and-checks.md#813-checks-and-failure-witnesses).

### Make parameter default shape and evaluation explicit

Iris 0.1 evaluates defaults even when the caller supplies an override.
Defaults can be arrays, but an override becomes a scalar chosen only by the
default's value type. Consider explicit parameter type and shape rules,
and whether defaults should be lazy. Found in
[§9.2](../spec/0.1/09-params-and-instances.md#92-parameter-evaluation-and-conversion).

### Separate ordinal and name selection

Iris 0.1 gives integer conversion priority over names, treats overflowing
integer spellings as names, rejects float-valued names, and lets an empty
selector match an absent or unusable name. Without a selector, later passes
also see the first retained instance's published data while establishing
that the file contains only one instance. Consider explicit selection modes,
a distinct representation for an absent name, and isolated instance frames.
Found in
[§9.4](../spec/0.1/09-params-and-instances.md#94-instance-selection).

### Make deferred rejection independent of evolving names

Iris 0.1 tests the current name at each rejection. A later immediate failure
can become primary ahead of an earlier deferred one, and repeated sections
captures can rename the instance. Review selection and rejection together
so failure order remains useful. Found in
[§9.5](../spec/0.1/09-params-and-instances.md#95-deferred-failures-in-skipped-instances).

### Review catalog recovery and selector handling

Iris 0.1 catalog ignores valid selectors but rejects zero and negative
integer selectors. Missing-arm recovery depends on whether any data remains
at the rejection site, so a final missing arm is hard. Review a consistent
catalog parameter policy and explicit recovery limits. Found in
[§9.6](../spec/0.1/09-params-and-instances.md#96-catalog-results).

### Review work-budget charges and input-size allowance

Iris 0.1 idle work accumulates for the whole operation, including after
input consumption. Empty ordinary arrays charge positive dimension prefixes;
zero-column alphabets charge the row count once, while missing-row filling
has no independent charge. Expression effort charges selected leaves and
each distinct lifted dependency at each level, even before short circuit,
but whole-name copies, scalar arithmetic, string comparison, and sorting
have no independent charge. Equivalent conditions written with different
record denotations can therefore consume different effort. Comments,
padding, and ignored or unread tails increase the allowance, including for
an early selected instance. Review whether these events and the raw-input
allowance remain useful for Iris 1.0. Found in
[chapter 10](../spec/0.1/10-work-budgets.md); see also the empty-array and
structural-diagnostic ideas above.

### Review dzn numeric formatting

Iris 0.1 dzn uses an increasing-precision search and `%g`-style notation
thresholds, exponent signs, and exponent padding, unlike canonical JSON.
Decide whether Iris 1.0 should use a conventional shortest round-trip
algorithm. Found while specifying
[appendix B.3](../spec/0.1/appendix-b-dzn.md#b3-floating-point-text).

### Review shape-dependent dzn representation

Equal row lengths can change nested tuple output into a matrix, empty
arrays lose lower extents, and depth 7 switches to tuples even for
rectangular data. Decide whether Iris 1.0 should retain a stable
representation and more type or shape information. Found in
[appendix B.5](../spec/0.1/appendix-b-dzn.md#b5-rectangular-arrays-and-empty-dimensions)
and [B.6](../spec/0.1/appendix-b-dzn.md#b6-ragged-and-deeper-arrays).

### Make the minimum integer directly spellable in expressions

Iris 0.1 rejects `-9223372036854775808` because its positive literal token
is validated before unary negation. The equivalent
`-9223372036854775807-1` works. Decide how unary negation and literal
magnitude should interact in Iris 1.0. Found in
[§5.5](../spec/0.1/05-reader-specs.md#55-numbers), whose
`reader-number-overflow` and `reader-number-spellings` examples show both
forms.

### Consider arithmetic on float data

Iris 0.1 reads float and num data, compares mixed numeric scalars, applies
integer offsets to floats, and permits float unary negation, but every
binary arithmetic operator requires integer scalars. Consider float
arithmetic for Iris 1.0, with explicit rounding, overflow, and result-type
rules. Found in [§8.5](../spec/0.1/08-expressions-and-checks.md#85-floating-point-and-mixed-numeric-values),
including `expressions-float-add` and `expressions-mixed-add`.

### Add variant types for values with several forms

Many inputs give one position several forms: a command keyword followed by
its own arguments (`fd 10`, `lt 90`), an integer or the keyword `undo` and
a count, a number or a range `3-9`, a colour and a size in either order.
Iris 0.1 reads keyword forms with `op: word` and `if`, padding every
branch-only field (`x[0]: int`, `let x = 0`) so that each repetition
defines it; forms told apart by token type, line shape, or position read
only as untyped words or text. Consider a `type` with constructors, each
with a recognizer (a keyword, the first field's type, or a line pattern)
and typed fields, read by ordered choice with at most one token or one line
of lookahead:

```iris
type command =
  | undo "undo" (count: 1..)
  | throw (positions: -10000..10000)
```

Decide how dzn represents a variant: an enum column for the tag and one
column per field needs a declared default where a constructor lacks the
field. Found in a survey of the 1000 most-solved Open Kattis problems: 43
of 232 specced formats have variants, told apart by keyword (31), line
shape (17), token type (6), glyph (5), or position (2); 4 of 6 failed first
attempts in one batch broke the padding rule.

### Read lines and pictures with their spaces

`rest` trims edge spaces and blank lines are skipped, so Iris 0.1 cannot
read a line that is only spaces, a message whose edge spaces matter, an
empty file name, or a grid whose spaces are cells (a peg board with blank
off-board squares). Blank lines that separate groups are lost too.
Consider a raw line read that keeps every byte, and a picture read of raw
lines as a character grid with a cell alphabet, a row count or
`until blank`, and a width that is given or padded to the longest row. The
width check also covers a constraint 0.1 cannot check: 22 of 232 specs in
the same Kattis survey list row width as unchecked. Found in that survey: 9
problems need spaces kept, 2 need blank-line groups.

### Read ASCII-art glyphs as variants

Some pictures draw values: digits as 3×5 glyphs of `*` with a blank column
between them, a sum drawn in 5×7 glyphs, chessboard squares such as `.r.`
and `:q:` inside a `+---+` frame. Iris 0.1 reads the framed board with
`separators "|+"` and an alphabet, but cannot name a three-character square
as one value, and cannot read the others at all. Building on variant types
and picture reads, consider splitting a picture into tiles (fixed width
with a gap, split at gutter columns, or framed) and reading each tile as a
variant whose constructors are pictures, with captures inside a glyph like
those of a line pattern and a fallback constructor for unknown drawings.
Found in the same Kattis survey, where 5 of 1000 problems are ASCII art;
the feature may follow the other two.

### Read integers beyond 64 bits

Iris 0.1 numbers are 64-bit decimal. `tokens "0123456789"` with `list
digit: 0..9 until eol` reads one big integer per line as a digit array, but
two big integers on one line run together, and the value is not a number
for checks. Octal and other radixes have the same gap. Consider a big
integer type, or a digit-string read per token, and radix reads. Found in
the same Kattis survey: 11 problems have big integers.

### Allow an empty same-line list

`list ... until eol` never returns an empty list: on an exhausted line it
reads on into the next. A line such as `gmp:` with zero dependencies
after the target therefore cannot be read as a target and an empty list;
`rest` also moves on and reads the next line. Consider a line-local list
that can be empty, and an empty `rest` at the end of a line. Found in the same Kattis survey (`builddeps`).
