Use `sections` for lines identified by keywords. Arms match in whatever order
the lines appear, and an arm's body runs as soon as it matches. This suits
headers whose order varies, as in [TSPLIB](/formats/tsplib/).

## Read headers and a body

The coordinate body uses `n`, so `DIMENSION` must occur before
`NODE_COORD_SECTION`. Other header arms may occur in either order. Names are
defined when their arms run; sections do not rearrange input or defer bodies.

## Required, optional and last arms

An ordinary arm must match exactly once. `optional` changes that to zero or
one, so guard an optional capture with `defined` before using it. `last` ends
sections after the selected arm's body runs. It still checks for missing
required arms. The [job shop tutorial](/tutorial/job-shop/#finish-with-the-library-reader)
uses a last arm to leave the next instance header for the next pass.

A terminator is tested before arms. Actual end of input also ends sections,
even with `until "EOF"`. On completion, a missing required arm reports
[E-LINE-MATCH](/specification/0.1/errors/#e-line-match).

## Repeated and unknown lines

A repeated dimension is an error even when its value is unchanged:

This is [E-SECTIONS-REPEATED](/specification/0.1/errors/#e-sections-repeated).
Optional arms also reject a second match. Use a repeat for repeated records;
a sections arm does not collect repeated headers into an array.

Unknown lines report
[E-SECTIONS-UNEXPECTED](/specification/0.1/errors/#e-sections-unexpected).
`skip other` discards unmatched lines when the format permits irrelevant text.
Keep sections strict when an unknown keyword is likely to be a spelling error.
If two patterns could match, the first complete match wins.
