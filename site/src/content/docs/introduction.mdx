Iris is a specification language for structured text formats. A program in
Iris is a *reader spec*. It describes one format: which values a file
contains, how they are laid out, how they are collected into arrays, and which
conditions they must satisfy. Given a reader spec and an input file, Iris
either returns the file's contents as named, typed data or rejects the file
with the position and the statement that failed.

The formats Iris was built for are the benchmark and instance files of
combinatorial problems, such as SAT formulas, travelling salesman instances
and scheduling problems. Any line- and token-oriented text format is a
candidate. The same reader spec works in the command-line tool, in a program
that embeds an implementation, and in the [playground](/playground/).

## A first example: DIMACS CNF

This small [DIMACS CNF](/formats/dimacs-cnf/) file describes a Boolean formula
with three variables and three clauses. A positive number names a variable;
a negative number negates it. Each clause ends with `0`.

The reader spec for DIMACS CNF in the [format library](/formats/) skips
comment lines beginning with `c`, captures the two counts from the `p cnf`
header, then reads one list per clause. The range on each literal checks that it refers to a
declared variable. The sentinel `0` ends each list and is consumed without being
stored. `stop "%"` handles the end marker used by SATLIB files.

</div>

[Build the CLI](/tools/cli/#build-from-source), then run this command from the
repository root. The paths are the library's actual files. The `--dzn` option
prints the data in MiniZinc's data format:

The data has the two integer counts and `clause`, an array of integers with
one row per clause. Rows can have different lengths, so the array is ragged.
The CLI can also print [JSON or a summary](/tools/cli/#read-input), and a
[Rust program](/using/rust/) reads the same data through typed accessors.

## Iris and Gecode

Iris began as the instance reader in the constraint solver
[Gecode](https://www.gecode.org), which uses reader specs to load benchmark
files for its examples. The [Iris Language Specification](/specification/0.1/)
defines the language independently of Gecode, and its
[appendix C](/specification/0.1/appendix-c-differences/) lists the deliberate
differences from Gecode's reader. The reader specs in the format
library are Gecode's.

Rust is the reference implementation and the source of the command-line tool
and the playground. A Python binding and native C++ and Java implementations
are planned; see [using Iris from a program](/using/rust/).
