The `iris` command checks reader specs and reads text input using Iris 0.1.
It also formats reader specs, starts the [language server](/tools/lsp/), and
runs the shared conformance suite.

## Build from source

Use Rust 1.88 or newer with Cargo. In the repository's `rust/` directory, run:

<CheckedExample id="build-cli" />

The executable is `rust/target/debug/iris` relative to the repository root
(`iris.exe` on Windows). If you set `CARGO_TARGET_DIR`, use that directory's
`debug` subdirectory instead. Add the executable's directory to `PATH` for the
commands below. All of them run from the repository root.

Building from source is the only installation path for now. The Rust packages
are at version 0.1.0 and are not published; crates.io publication and binary
releases are planned.

## Supply parameters

Repeat `--param NAME=VALUE` for caller parameters. Values remain strings until
the reader spec converts them. The first `=` separates name and value; later
assignments to the same name replace earlier ones.

## Run conformance cases

The conformance runner compares an implementation's driver with the language-neutral
cases. Build the Rust driver in `rust/`:

<CheckedExample id="build-driver" />

Then run from the repository root, with `iris` on `PATH` and the default Cargo
target directory. If you changed `CARGO_TARGET_DIR`, adjust the driver path:

<CheckedExample id="conformance" />

Explicit roots are relative to the current directory. With no root, the default
is `conformance/cases/0.1`. `--filter` selects a path substring; `--version` defaults
to `0.1`; `--timeout` defaults to 30 seconds per case. `--driver-id` selects precise
known-failure annotations for that driver. Rust needs no exemptions.
The driver argument is a command string parsed with shell quoting, without shell
execution or expansion.

See the [conformance suite](https://github.com/Gecode/iris/blob/main/conformance/README.md)
for its driver protocol and case format.

## Errors and exit status

Checks and reads exit 0 on success, 1 for language, file or resource errors, and
2 for incorrect usage. Diagnostics show a location, a source excerpt and a caret;
read errors also identify the active reader-spec line. A failed read prints no
partial data. The [format library](/formats/dimacs-cnf/#case-literal-out-of-range)
shows a real failed read; the [Specification](/specification/0.1/errors/)
defines the error codes and their order.

For conformance, exit 1 means a failure or unexpected pass; exit 2 also covers
configuration, case-loading and zero-selection errors.
